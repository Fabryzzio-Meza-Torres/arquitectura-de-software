# Acceptance criteria

These criteria provide the testable detail behind the functional and non-functional
backlogs.

## AC-1 — Identity and academic scope

- **AC-1.1** Each primary role signs in with assigned credentials and sees only permitted
  actions.
- **AC-1.2** A Rural Student sees only enrolled courses, personal submissions, grades and
  feedback.
- **AC-1.3** A Rural Teacher sees only assigned courses, classrooms and minimum student data.
- **AC-1.4** Only a technical account can configure courses, classrooms, groups, enrollments
  and teacher assignments.

## AC-2 — Package preparation and controlled AI

- **AC-2.1** A Government Teacher creates a package for one period, associates preconfigured
  destinations, uploads supported formats, previews files and publishes an identified
  version with a manifest.
- **AC-2.2** Reaching a configured token limit prevents further AI generation under that
  limit and explains the recorded consumption, while manual upload and publication remain
  available.
- **AC-2.3** The AI assistant uses the same representative benchmark as the baseline and
  consumes at least 40% fewer tokens while producing equivalent required output.
- **AC-2.4** A correction creates a new version and never overwrites an active school copy.

## AC-3 — Distribution and integrity

- **AC-3.1** A published package retains the same version identity and manifest through the
  cloud, departmental server and school server.
- **AC-3.2** Interrupting a large file triggers automatic retry or resume; partial content is
  not activated.
- **AC-3.3** A school activates the new version only after every file matches its manifest.
- **AC-3.4** Failed verification keeps the previous active version available and identifies
  the content requiring another transfer.
- **AC-3.5** Temporary transfer cache is retained until synchronization and integrity are
  confirmed, then removed without deleting the active package.

## AC-4 — Rural Teacher planning and classroom use

- **AC-4.1** During planning week, Gaspar can review the complete package for the coming
  period and assigned classrooms.
- **AC-4.2** Gaspar can view, play, download and print active material over the school LAN
  while external internet is unavailable.
- **AC-4.3** After initial orientation, a representative Rural Teacher completes sign-in,
  package lookup, material opening, task creation and grading without technical assistance.

## AC-5 — Rural Student access

- **AC-5.1** Baltasar can use the target XO laptop to access enrolled-course material over
  the LAN without an external service.
- **AC-5.2** Baltasar can view or download supported files and open editable documents with a
  compatible installed application.
- **AC-5.3** The interface exposes no forum, student-comment or academic-configuration control.

## AC-6 — Tasks, submissions and grades

- **AC-6.1** Gaspar can create and schedule a task or announcement for an assigned classroom.
- **AC-6.2** Baltasar can submit an allowed file; Gaspar can grade it and leave feedback;
  Baltasar can read the result without commenting.
- **AC-6.3** Gaspar can record period grades and each student can view only the personal grade.
- **AC-6.4** The platform offers no Ministry grade export or automatic Ministry registration.

## AC-7 — School capacity and degraded connectivity

- **AC-7.1** The school server supports material-access flows from 12 physical classrooms in
  parallel without requests failing because of server saturation.
- **AC-7.2** Loss of external internet leaves the active package available over the LAN.
- **AC-7.3** Failure of the AI assistant does not prevent manual package upload, preview or
  publication.

## Architecture exit gate

The architecture diagram is acceptable only if it shows the complete committed path:
**Flow 1, then Flow 2, then Flow 3**, including manifest verification, retry or resume,
atomic activation, local LAN access and the previous-version fallback.
