# Non-functional requirements — Balbuena EduKanvas

These quality requirements use only confirmed case-study targets and product decisions. No
unsupported national scale, latency, availability, RTO or RPO figure is treated as a
contractual target.

| ID | Non-functional requirement |
| --- | --- |
| NFR-01 | **Required hierarchical network topology.** The solution must operate through the defined Lima, cloud, departmental-server, school-server and school-LAN topology. A classroom client must obtain active material from the school server rather than requiring a direct Lima connection. |
| NFR-02 | **Classroom operation without stable external internet.** After a package becomes active, the material-access flows for Rural Teachers and Rural Students must remain usable over the school LAN while the external connection is unavailable or unstable. |
| NFR-03 | **Twelve-classroom school capacity.** A school server must support simultaneous material-access flows from 12 physical classrooms without requests failing because of server saturation. The test must use the school LAN and representative package files. |
| NFR-04 | **Chunked and resumable large-file transfer.** Large files must be divided into independently confirmed chunks. After connectivity interruption, an upload or download must continue from the last confirmed chunk without retransmitting the complete file or discarding already confirmed partial data. |
| NFR-05 | **Automatic and manual retry initiation.** An interrupted transfer must retry when the system detects restored connectivity. A scheduled periodic check must trigger retry when reconnection was not detected, and an authorized user must also be able to request a manual retry. |
| NFR-06 | **Single active retry per file.** If reconnection detection, the periodic check or a manual request triggers retry for the same file concurrently, the system must allow only one worker to process that file at a time. Other triggers must reuse or observe the active attempt and must not send the same chunk twice. |
| NFR-07 | **Reliable point-to-point and multicast completion.** Point-to-point transfers from teacher to central service, central service to department and department to one school must use the chunked retry rules. Regional multicast may provide the initial transmission, but every receiving school must preserve confirmed chunks, detect missing chunks from the manifest and complete repair through automatic resumable point-to-point transfer before activation. |
| NFR-08 | **Batch synchronization and recoverable pending data.** The system must process synchronization in batches when connectivity is limited and retain a recoverable backup of pending or unconfirmed batch data. Connectivity loss must not erase the batch or require already confirmed data to be recreated. |
| NFR-09 | **Manifest-based file integrity.** A received file must be considered complete only when its computed integrity value matches the value in the package manifest. A mismatch must leave the file inactive, preserve valid chunks and identify missing or corrupt chunks for repair. |
| NFR-10 | **Atomic package-version activation.** Users must see either the previous complete version or the new complete version, never mixed versions or partial files during activation. |
| NFR-11 | **Safe temporary-cache lifecycle.** Temporary transfer cache must remain available until synchronization and integrity are confirmed, then be deleted without removing the active package before the academic period closes. |
| NFR-12 | **Automatic end-of-period file deletion.** At the close of each two-month academic period, the system must automatically delete the period's files from active school storage to free capacity and record whether the deletion completed or failed. |
| NFR-13 | **At least 40% lower AI-token consumption.** The optimized AI assistant must consume at least 40% fewer total tokens than the baseline when both execute the same representative workload and produce equivalent required educational outputs. |
| NFR-14 | **Auditable AI-token measurement.** The system must retain token consumption by Government Teacher, course, model and academic period so the configured limits and 40% reduction can be reproduced and verified. |
| NFR-15 | **Rural Teacher task usability after orientation.** In a representative usability test after initial orientation, a Rural Teacher must complete sign-in, active-package lookup, material opening, task creation and grading without technical assistance. |
| NFR-16 | **Plain-language package and synchronization states.** Interfaces must present package and synchronization state with the defined labels `pending`, `synchronizing`, `verified`, `active` or `failed`, plus an actionable explanation when the state is `failed`. |
| NFR-17 | **XO-laptop classroom compatibility.** The Rural Student flow for sign-in, material access, file submission and grade viewing must run on the target XO laptop without requiring an external service during class. |
| NFR-18 | **Role-appropriate interface exposure.** The interface must hide academic-configuration and comment-publication controls from Rural Students. After training, it must allow a Rural Teacher to create and manage courses, grades, classrooms, groups, enrollments and teacher assignments only within the authorized school. |
| NFR-19 | **Student academic-record isolation.** A Rural Student must be unable to retrieve another student's courses, submissions, grades or feedback through the interface or a direct request. The denied request must return none of the protected record. |
| NFR-20 | **Student-data minimization.** Teacher-facing student data must be limited to full name, enrollment identifier and academic records required for the assigned classroom. The platform must not require an expanded social or personal profile. |
| NFR-21 | **Traceable academic and publication changes.** Package publications, version changes, submissions and grades must record the acting identity, time, target and affected object identifier so an authorized reviewer can reconstruct the change. |
| NFR-22 | **Protected credentials.** User credentials must not be stored or transmitted in plaintext. Authentication failures must not expose credential values or another user's protected data. |
| NFR-23 | **Explicit component boundaries.** The architecture must separate identity, content production, AI consumption, distribution and synchronization, and academic activity into components with explicit responsibilities and interfaces. |
| NFR-24 | **AI failure isolation.** An unavailable or failed AI assistant must not prevent a Government Teacher from uploading, previewing or publishing material created without AI. |
| NFR-25 | **Scope-limited resilience.** The solution does not claim 100% availability or advanced high availability. It must demonstrate local continuity for active content, chunk preservation, coordinated retries, multicast repair, manifest integrity and previous-version fallback required by this scope. |
