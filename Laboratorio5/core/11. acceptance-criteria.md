# 11. Acceptance criteria

| ID | Observable criterion | Flows |
| --- | --- | --- |
| AC-01 | Two registrations with the same key and operation produce one ticket and ID; history is not duplicated. | F1 |
| AC-02 | A client report starts a one-day response deadline and keeps it after escalation; an engineering report starts a three-day response deadline. Remaining time and the first substantive human response are visible. | F1-F3 |
| AC-03 | Support can close a user error or accept a proposal after performing the solution; no LLM outcome changes a ticket to `Resolved` on its own. | F1, F3 |
| AC-04 | Every proposal shows sources or the lack of them; when information is missing, users can request it, and when the LLM fails, they can use human analysis or escalation without losing the ticket. | F1-F3, F5 |
| AC-05 | A destructive proposed action is blocked before any write. The approved intervention is performed by a person outside the LLM and is audited. | F5 |
| AC-06 | Reopening retains history and its reason, shows live status, and invalidates related cache. | F4 |
| AC-07 | Retries of the same escalation do not create another effective assignment or notification; a Slack failure leaves a recoverable, visible event. | F2 |
| AC-08 | Under 10,000 incidents per week and 50-100 engineers, load testing shows persistent queuing, limits, and recovery without ticket loss or duplication; any SLA breach is reported. | F1-F3, F5 |
| AC-09 | A timeout or repeated failure opens the circuit breaker, provides fallback, and routes the ticket to human review; no unlimited LLM or subagent loop occurs. | F5 |
| AC-10 | A common question reuses only validated, current knowledge; ticket changes do not return stale closed or reopened states. | F1, F4 |
| AC-11 | A person can trace author, reason, date, proposal, evidence, decision, and owner for every transition; only validated resolved tickets enter the nightly RAG index. | F1-F4 |
| AC-12 | Diagram review identifies critical dependencies, single points of failure, degradation paths, and boundaries among the LLM, read-only tools, sandbox, Slack, and human decisions. | F1-F5 |
