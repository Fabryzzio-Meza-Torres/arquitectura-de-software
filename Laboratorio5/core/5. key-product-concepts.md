# 5. Key product concepts

| Concept | Meaning |
| --- | --- |
| Ticket | A unique incident record with type, client or source area, priority, deadline, status, owner, history, and human decisions. |
| Customer Escalation | A client report still handled by support; response is due within one day. |
| Support Escalation | A client report that support forwards to engineering after assessing it; it keeps the one-day deadline of its client origin. |
| Engineering Escalation | An incident initiated by engineering; response is due within three days. |
| Status | `Open`, `Under analysis`, `Awaiting information`, `Escalated`, `Resolved`, or `Reopened`; every transition preserves author, reason, and date. |
| LLM proposal | A diagnosis or suggested steps with evidence and warnings; it is neither an executed solution nor closure approval. |
| Human decision | Support or engineering accepts, corrects, or rejects a proposal, performs the solution outside the LLM, and records the outcome. |
| Approval Gate | Stops every risky-action suggestion for explicit review; even when approved, a person performs the action. |
| Idempotency | Repeating the same operation with the same key returns the same result; neither the ticket nor its history is duplicated. |
| RAG and cache | RAG retrieves approved knowledge; cache accelerates reusable answers, but the live ticket status is read from the current record. |
