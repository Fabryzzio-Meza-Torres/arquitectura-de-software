## 5. Requisitos No Funcionales

| ID | Requisito no funcional |
|---|---|
| RNF-01 | El sistema debe mantener una disponibilidad mensual mínima de 99.9 %. |
| RNF-02 | El sistema debe recuperar sus funciones críticas en menos de 5 minutos después de una caída. |
| RNF-03 | La información clínica esencial debe mostrarse en menos de 1 segundo bajo condiciones normales. |
| RNF-04 | Las alertas críticas y actualizaciones deben enviarse por notificaciones push simultáneas al equipo conectado en un máximo de 2s, garantizando la persistencia local de la información en caso de intermitencia de red. |
| RNF-05 | El sistema debe permitir incorporar nuevos hospitales, unidades, camas y usuarios sin modificar sus funciones principales. |
| RNF-06 | El sistema debe exigir autenticación y aplicar permisos según el rol del usuario. |
| RNF-07 | La información clínica debe permanecer cifrada durante su transmisión y almacenamiento. |
| RNF-08 | Un usuario capacitado debe poder generar una alerta de emergencia manual en máximo tres pasos, activando al instante el protocolo de localización rápida del médico encargado para reducir tiempos de reacción. |
